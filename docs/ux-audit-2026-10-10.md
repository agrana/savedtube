# SavedTube UX Audit — 2026-10-10

## Scope

First exploratory audit of the public landing/demo and the watch-entry experience. The intended critical journey is:

> Discover SavedTube → understand the demo path → select a lesson → play the lesson → move to the next lesson → sign in and create a path.

The authenticated path dashboard, path creation, path detail, exclusion, and resume journeys require a configured local NextAuth provider and remain pending.

## Findings

### UX-001 — Primary CTA has no local visible outcome when auth configuration is unavailable

- **Severity:** P1 in the audit environment; P2 for production hardening
- **Route:** `/`
- **Control:** `Build your own path`
- **Steps:**
  1. Open the public landing page.
  2. Click `Build your own path`.
  3. Observe the page.
- **Observed:** No visible navigation, modal, loading state, status message, or error appeared locally. The browser console remained clean.
- **Expected:** The user should either enter Google sign-in, navigate to the authenticated dashboard, or receive a clear actionable configuration/authentication error.
- **Evidence:** `DemoPathLanding.tsx` calls `signIn('google', { callbackUrl: '/' })`; the local route ultimately resolves to the NextAuth configuration error page when auth is unavailable.
- **Fix direction:** Add a visible sign-in transition/error state and verify the configured deployment. The product should never make a primary CTA appear inert.

### UX-002 — Public landing page presents multiple competing next actions

- **Severity:** P2
- **Route:** `/`
- **Observed:** The hero presents `Build your own path` and `Watch the demo` with similar prominence. The page also contains `Demo`, `Pro`, `Upgrade`, and a lower `Try the demo first` action.
- **User impact:** A first-time visitor must choose between creating and consuming before the product has fully demonstrated the learning loop.
- **Fix direction:** Define one primary first-session action. Recommended hierarchy: `Watch the demo` as the low-friction primary action and `Build your own path` as the authenticated conversion action, or explicitly explain the difference beside both actions.

### UX-003 — Demo lesson context is useful but the learning action is implicit

- **Severity:** P2
- **Route:** `/#demo`
- **Observed:** The selected lesson shows title, channel, stage objective, and `Previous`/`Next`, but the surrounding UI does not state what the user should do after watching or how SavedTube turns viewing into practice.
- **Fix direction:** Add a compact cue such as `Watch the lesson, then practice the key interval` or `Next: watch the following lesson`. Keep the cue adjacent to the player and sequence controls.

### UX-004 — The public demo does not expose the interval/practice behavior promised in product copy

- **Severity:** P2
- **Route:** `/`
- **Observed:** The landing copy says the product supports `practice with loops`, while the public demo exposes a plain YouTube player and lesson navigation. Interval management exists in the authenticated watch route, but the public demo does not preview that behavior.
- **Fix direction:** Either show a small non-interactive practice preview in the demo or narrow the public copy so the promise matches the demonstrated experience.

### UX-005 — Authenticated audit is blocked by local provider configuration

- **Severity:** Audit blocker
- **Routes:** `/paths`, `/paths/new`
- **Observed:** Both routes resolve to the NextAuth configuration error.
- **Fix direction:** Establish a safe local/staging auth profile for UX auditing. Keep credentials outside the repository. Add a documented audit setup check that confirms sign-in, session creation, and callback routing before exploratory QA begins.

### UX-006 — Playback reset requires a state-specific regression audit

- **Severity:** P1 until verified
- **Surface:** `YouTubePlayer`
- **Static evidence:** A 200 ms monitor checks interval state. When `loopEnabled` is true and playback passes the final interval, it calls `seekTo(sortedIntervals[0].startTime, true)`. With looping disabled, ordinary playback should not seek, although it can pause at the end of the final interval.
- **Current status:** The behavior has not been reproduced in a configured authenticated watch session.
- **Fix direction:** Test these states separately: no intervals, intervals with loop off, intervals with loop on, manual play-through, and playback after the final interval. Capture every `seekTo` call and confirm whether the reset is intentional or stale state.

## Audit blockers

1. Local NextAuth provider configuration is unavailable, preventing authenticated browser journeys.
2. The public demo uses a real YouTube iframe, so full-duration playback verification depends on external YouTube availability and browser playback behavior.
3. The automated browser can inspect the iframe and controls but does not replace a human full-duration watch test for the reported reset.

## Recommended next audit slice

Configure a safe local/staging authentication session, then run this charter:

1. Sign in from the landing page.
2. Confirm the dashboard shows existing paths or a useful empty state.
3. Open `Create new path`.
4. Submit a goal and background.
5. Observe loading, failure, retry, and post-create states.
6. Open the resulting path.
7. Start a video and watch through the reported failure point.
8. Repeat with interval loop off, interval loop on, and manual play-through.
9. Exclude one video and verify active-path, review, restore, map, list, watch, and progress consistency.
10. Return to the dashboard and resume the path.

Each defect should become a separate atomic Cursor Agent task with a reproduction, regression check, and browser retest.
